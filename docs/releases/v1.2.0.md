# AutoCAR v1.2.0

面向个人部署的功能与稳定性更新：更新 Web H2/H3 握手配置，增加显式开启的 H3
TLS 会话恢复，并修复连接限额、失败请求清理和 HTTP 响应尾部字段（trailers）。
**本版本包含配置迁移要求，不是无条件兼容替换；升级前请检查客户端 H3 配置。**

## 主要变化

- H3 默认画像更新为 `chrome-2026-10`，新增 `chrome-2026-10-resume`：同一
  客户端重连时可使用有效票据恢复 TLS 1.3 会话。默认仍为完整握手，所有画像均
  禁用 0-RTT，每条新物理连接仍重新认证。缓存按客户端隔离、仅驻留内存。
- 新增 `--h2-fingerprint`，支持 `chrome-133`、`chrome-155` 和 `native`。
  新生成的 Web `init` 配置明确选择 `chrome-155`；旧配置省略该字段时仍使用
  `chrome-133`。该选项也用于 `web-auto` 的 H2 回退路径。
- 改善 H2 TLS 会话恢复与 HelloRetryRequest 兼容性，避免失败响应清理拖延拨号
  返回，同时保留共享连接上其他流的可用性。
- 修复 native QUIC/TLS 全局连接限额共享，约束未认证连接及空闲 QUIC 会话；
  保留 HTTP 响应中正文结束时才产生的正常 trailers，并过滤禁止字段和
  `Connection` 指定的逐跳字段。正文截断仍作为失败处理。
- 修复证书与私钥输出路径别名冲突、SOCKS5 认证期间的关闭取消、令牌标准输出
  失败处理，以及 Web 临时 TCP/UDP 端口冲突重试。
- 更新 Go 与网络依赖。源码构建最低要求为 Go 1.27.2；H2/Web H3 使用固定版本
  的维护分支，native QUIC 保持独立使用上游模块。

## 升级与回滚

- 显式 `h3-fingerprint: chrome-2026-08` 已被拒绝。请直接修改配置文件为
  `chrome-2026-10`，或按需选择 `native`；仅追加命令行覆盖不能绕过旧配置项
  检查。省略该字段的旧配置会采用十月画像，改变客户端握手。
- 新 H3 会话恢复必须显式选择 `chrome-2026-10-resume`；改回
  `chrome-2026-10` 即恢复完整握手。`h3-fingerprint=native` 仍属于 Web H3，
  不会切换为 native relay 协议。仅运行服务端无需修改客户端画像选项。
- native `--max-connections` 现在由 QUIC 与 TLS 两个监听器共享。
  `--max-client-fallback-connections` 不得超过 `--max-streams` 或
  `--max-connections`；默认取 `32`、最大流数、最大连接数中的最小值。
  原先超过这些限制的配置需要调整，否则启动和离线检查会拒绝它。
- 保留旧二进制、配置和凭据，先运行双端 `--check`，再验证真实认证连接。
  回滚 v1.1.0 时恢复旧配置，不携带新增 H2 选项或十月 H3 画像值。
- Web 默认值与 v1.1.0 一致。更早版本升级时，仍须准备明确的网站 cover 并
  协调两端协议；显式 native/auto 配置继续有效。不要只替换一端并假定协议不变。

下载后先验证 `SHA256SUMS`。迁移细节见
[部署说明](https://github.com/cppla/autocar/blob/v1.2.0/docs/DEPLOYMENT.md)。

## 能力与验证边界

- H2 仅承载 TCP；H3 到 H2 的回退只影响新 TCP 流，不迁移已有流，也不承载 UDP。
  H3 CONNECT-UDP 单包上限仍为 1,150 字节，无分片或 Capsule 数据回退。
- Web 不支持 mTLS 或 native fixed-rate pacing。H2 目标端 EOF 会结束 CONNECT
  响应并停止剩余上传；需要在目标 EOF 后继续上传的应用应使用 H3。
- 握手画像与功能回归不代表完整流量与真实浏览器等价。本版本不提供被动抗识别
  结论，也未量化 H3 会话恢复的延迟收益。
- 发布流程要求同一 main 提交通过 CI、CodeQL 和 Linux netem 检查，再执行
  质量检查、race、离线工具自测、漏洞扫描及四平台打包。准确的 Linux amd64
  安装包执行 38 项冒烟及 native 升级/回滚检查，回滚基线固定为 v1.0.0。
- 开发阶段一次 macOS 全量 race 运行出现原有 UDP 测试的物理 QUIC 拨号超时，
  原因尚未确定；该用例后续 20 次独立 race 运行及原顺序全量重放均通过。
  未跳过测试或放宽断言，记录见 [PR #81](https://github.com/cppla/autocar/pull/81)。
- 发布包覆盖 Linux amd64/arm64、macOS arm64、Windows amd64，内含可执行文件、
  许可证与第三方许可清单，并提供 `SHA256SUMS`。交叉构建和元数据检查不等于
  每种平台均完成原生部署验收，仍需按实际网络、证书与应用验证。
