# AutoCAR v1.1.0

面向个人部署的功能增强与稳定性更新。新部署默认启用 Web-cover：服务端默认
`web`，客户端、`doctor` 和隧道基准测试默认 `web-auto`（H3 优先，新 TCP 流在
传输失败时回退 H2）。这次默认值变更不代表流量与真实浏览器等价或抗识别效果
已经得到验证。

## 主要变化

- `autocar init` 默认生成匹配的 Web-cover 双端配置、自签证书、独立网站目录
  和受保护的随机令牌；`init --protocol=native` 保留 native/auto 部署方式。
- 支持 JSON 配置，命令行可覆盖配置项，文件路径相对于配置目录解析。
  `client --check`、`server --check` 提供离线检查，不连接网络或打开监听器。
- `doctor` 提供认证 TCP 路径检查、传输状态和稳定错误码；可显式选择 UDP DNS
  检查，必须指定测试目标和 DNS 名称，不默认访问第三方解析器。
- 完善网站上游代理的流式请求/响应、trailers、WebSocket 和固定公开源会话支持；
  静态网站目录限制路径逃逸和私密文件访问。
- 改善 H2 连接复用、TLS 恢复、超时和退出资源回收，以及 H3 连接初始化、
  认证和取消边界；完善 native QUIC/TLS 的取消、回退和关闭行为。
- 修复 SOCKS5 UDP 会话与目标队列隔离、HTTP 代理流式传输、基准测试退出回收、
  native 自适应 pacing 和命令行意外位置参数处理。

## 升级前必须确认

显式设置了 `protocol: native` 和 `transport: auto` 的旧配置不变。省略这些字段
的旧启动命令或配置会采用新的 Web 默认值，不能只更换一端二进制并假定协议不变。

- 保留旧部署：升级前在服务端明确设置 `--protocol=native`，客户端明确设置
  `--transport=auto`；使用 JSON 时补上对应字段。
- 切换 Web-cover：准备独立网站目录或已获授权的固定 HTTP(S) 上游，服务端明确
  设置 `--cover-root` 或 `--cover-upstream` 二选一，客户端使用 `web-auto`。
  推荐在独立端口验证后同时切换两端，保留旧二进制、配置和凭据以便回滚。
- 手动启动时不会自动把当前目录当作网站，也不会自动访问第三方站点。
  缺少 cover 配置会明确拒绝启动；`init` 自动生成的仅是可替换的示例页面。
- v1.0.0 不支持 Web 参数；旧版 native 回滚需恢复原配置，不能携带新 Web 参数。
  v1.0.1 没有 `init`、JSON 配置和离线检查命令。

下载后先验证 `SHA256SUMS`，再按自己的网络、证书、出口策略和应用进行验收。

## 已知限制

- H2 只承载 TCP；H3 到 H2 的回退只影响新 TCP 流，不迁移已建立的流，也不承载 UDP。
  H3 CONNECT-UDP 单包上限为 1,150 字节，无分片或 Capsule 数据回退。
- Web 不支持 mTLS 和 native fixed-rate pacing。需要这些能力时显式使用 native。
- H2 目标端 EOF 会结束该 CONNECT 响应并停止剩余上传；收到 EOF 后仍需继续上传的
  应用应使用 H3。正常客户端上传半关闭仍允许接收目标回复。
- 默认握手画像、网站 cover 和本地功能测试不能证明与真实浏览器不可区分。
  未完成的全量被动识别实验不作为本版本的性能或抗识别结论。
- 交叉构建不等于所有目标系统均完成原生运行测试。

安装包覆盖 Linux amd64/arm64、macOS arm64、Windows amd64，内含可执行文件、
MIT 许可证和第三方许可清单。部署说明见 [DEPLOYMENT.md](../DEPLOYMENT.md)。
